# Задание: контрольный набор запросов для проверки поиска аналогов

## Контекст

Тестовое задание Mosaix: поиск аналогов позиций в истории закупок. База 2 381 строка: кабели и провода, оборудование РЗА и связи подстанций, видеонаблюдение и охрана, трубы и фитинги, металлопрокат и крепёж, ЖБИ, вентиляция, кабельные лотки, материалы, строки про погрузку и перевозку. Пользователь вводит наименование своими словами, поиск возвращает до пяти подходящих строк базы или честно говорит «не найдено».

Ты пишешь контрольный набор вслепую. Поиск строит другой исполнитель, его код ты не смотришь и не запускаешь. Так замер будет честным: поиск не подгонят под твои ответы.

## Источник

Только файл data/full/rows_all.json: список строк базы с полями row (номер строки Excel, от 2 до 2382), name (наименование как есть) и price. Другие файлы проекта не открывай: ни app/, ни scripts/, ни data/full/prep_all.jsonl, ни data/full/analysis/, ни docs/. Сетевых запросов не делай. Python и grep для поиска по базе можно.

Все ссылки на строки пиши номером строки Excel (поле row).

## Что сделать (задание, часть 3)

1. **20 контрольных запросов.** 16–17 запросов: возьми позицию из базы и перепиши её так, как написал бы другой человек: другие слова, сокращения, другая запись чисел. 3–4 запроса такие, для которых верного ответа в базе нет.
2. **Верные ответы.** Для каждого запроса все строки базы, которые допустимо выдать. Дели их на «та же позиция» (same) и «допустимая замена» (substitute). Ищи по базе широко: разные написания, латиница и кириллица, дубли, та же позиция в другой формулировке. Допустимую замену ставь только там, где специалист, скорее всего, согласится; причину пиши в note.
3. **Важная характеристика.** Для каждого запроса назови характеристику, которая решает (key), и перечисли строки того же вида, у которых она другая (wrong_key): например, тот же кабель другого сечения, та же труба другого диаметра. До 15 строк, самые похожие по тексту. Это нужно для метрики «сколько раз на первом месте позиция с другой важной характеристикой».

## Как переписывать

В одном запросе 1–3 приёма, смешивай их между запросами:
- сокращения и слова снабженца: «гофра», «ЖБИ», «к-т», «оцинк.», «кабель-канал» вместо «короб», «вентилятор крышный» вместо полного названия;
- другая запись чисел и размеров: «3*1.5», «3x1,5 мм2», «3 х 1.5 кв.мм»; «1,5» и «1.5»; размеры в другом порядке, «600х400» и «400х600»; «Ду25», «d25», «25 мм»;
- латиница вместо кириллицы в кодах и наоборот, лишние пробелы и дефисы, одна опечатка;
- убрать лишнее: номер пункта, название объекта, длинное описание; оставить то, что ввёл бы снабженец: вид изделия и главные характеристики;
- короткий запрос, часть наименования.

Не копируй строку дословно. Запрос должен оставаться однозначным для специалиста.

## Охват

- Разные категории из списка в контексте, не больше трёх запросов на одну категорию.
- Один запрос на услугу погрузки или перевозки.
- Один или два запроса на позиции с артикулом производителя.
- Два или три запроса, где в базе есть похожая по тексту позиция с другой важной характеристикой: сечение, диаметр, размер, мощность. Это главная ловушка задания: «кабель 3×1,5 и кабель 3×2,5 по тексту почти одинаковы, но это разные позиции».

## Запросы без ответа

- Хотя бы один трудный: вид изделия в базе есть, а нужной характеристики нет. Например, такого сечения у этой марки кабеля или такого диаметра у этой трубы в базе нет.
- Хотя бы один чужой: такого вида изделий в базе нет совсем.
- Отсутствие проверяй тщательно: grep по корню слова, по сокращениям, по латинице и кириллице, по числам в разных записях. Если сомневаешься, бери другой пример.

## Чего избегать

Не бери источником эти строки Excel и не пиши запросы про те же позиции: 3, 57, 81, 86, 159, 428, 467, 480, 559, 887, 1171, 1518, 1525, 1541, 1643, 1705, 1877, 2015, 2025, 2059. Не пиши запросы про кабель КВВГ 7х1,5, видеокамеры 2 Мп с вариофокальным объективом, ворота откатные, гофротрубу ПВХ 25 мм, ИБП, трансформатор сухой и огнетушитель. Это примеры из задания и набор для настройки поиска.

## Формат результата

Файл eval/control_set.json:

```json
{
  "version": 1,
  "created": "2026-10-17",
  "author": "агент-разметчик, вслепую к поиску",
  "row_ref": "номер строки Excel, поле row в data/full/rows_all.json",
  "queries": [
    {
      "id": "q01",
      "query": "текст запроса",
      "type": "answer или no_answer",
      "category": "кабели, РЗА, ...",
      "source": [123],
      "same": [123, 456],
      "substitute": [789],
      "key": "сечение 3х2,5 мм²",
      "wrong_key": [111, 222],
      "rewrite": "что изменено относительно строки базы",
      "note": "обоснование и сомнения"
    }
  ]
}
```

У запросов без ответа source, same и substitute пустые, в note объясни, как проверял отсутствие.

Файл eval/control_set.md: таблица на русском для проверки специалистом: id, запрос, тип, источник (номер строки и наименование), верные ответы с наименованиями, важная характеристика, сомнения.

## Проверь себя перед сдачей

- Каждый номер строки существует в базе.
- same и substitute не пересекаются с wrong_key.
- У каждого запроса типа answer есть хотя бы одна строка в same.
- Запросов ровно 20, без ответа от 3 до 4.

## Ответ исполнителю

Не больше 100 слов. Только числа: сколько запросов каждого типа, сколько в среднем строк в same, substitute и wrong_key, сколько запросов с сомнениями. Сами запросы и номера строк в ответе не пиши: исполнитель поиска не должен их видеть до замера.
