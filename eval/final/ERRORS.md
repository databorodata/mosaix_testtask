# Итоговый замер: сводка и разбор ошибок

Два итоговых набора по 20 запросов (16 с ответом, 4 без ответа) написаны вслепую разными моделями
(ChatGPT и Gemini) по брифу «перепишите позиции базы как написал бы другой человек», верные ответы
размечены ИИ-агентами, не видевшими кода поиска; спорные случаи помечены в наборах. Прогон один,
код заморожен (eval/FREEZE.md, v3), цифры объявлены до прогона (eval/JOURNAL.md).

## Цифры

| Вариант | Верный первым | В пятёрке | Другая важная характеристика первой | Честное «не найдено» | Ложное «не найдено» |
|---|---|---|---|---|---|
| Поиск по словам | 22 из 32 | 29 из 32 | 10 | 0 из 8 | 0 |
| Основной (обучаемое решение + реранкер) | 28 из 32 | 28 из 32 | 3 | 5 из 8 | 4 |
| Без реранкера (быстрый режим) | 30 из 32 | 30 из 32 | 5 | 3 из 8 | 2 |

По наборам (основной вариант): ChatGPT 14 из 16 первым, «не найдено» 3 из 4; Gemini 14 из 16, 2 из 4.
Счёт против поиска по словам по «верный первым»: 9 выигрышей, 3 проигрыша.
Подробные таблицы: eval/final/results.md и eval/final_gemini/results.md, построчно — details.md там же.

## Разбор ошибок

Все четыре ложных «не найдено» устроены одинаково: верная строка есть среди кандидатов,
но её балл 0.88–0.92 при пороге 0.92. Поиск находит — решение режет на пороге.

**1. «датчик открытия магнитоконтактный ДПМ 1» → ложное «не найдено».**
Верная строка 827 «Извещатель охранный контактный: ДПМ-1» набрала 0.91: марка ДПМ-1 совпала,
но вид «датчик» не считается тем же, что «извещатель», и признак вида утянул балл под порог.
Исправит: пара «датчик — извещатель» в словаре видов rules/synonyms.yaml; такие пары должны
копиться из подтверждений специалиста, код не меняется.

**2. «стяжка нейлоновая 3.6х200 белая» → ложное «не найдено».**
Верные строки 1207 и 1846 «Хомут-стяжка кабельная (бандаж), размер 3,6х200 мм» набрали 0.88 и 0.79:
размер совпал, но «стяжка» и «хомут-стяжка» для разбора — разные виды (составное слово через дефис).
Исправит: словарь видов плюс правило разбора «составной вид засчитывается по любой половине».

**3. «распредщит ПР-7 IP21 380/220В, вводной автомат MicroLogic 5.2E…» → ложное «не найдено».**
Верная строка 87 «Шкаф ввода и распределения электроэнергии ПР-7, IP21…» набрала 0.92 — на волоске
от порога 0.92. Жаргонного вида «распредщит» в базе нет. Это цена высокого порога: он выбран так,
чтобы честно молчать на запросах без ответа (5 из 8 против 0 из 8 у поиска по словам). Порог — ручка
бизнеса: ниже порог — меньше ложных отказов, больше лишнего на запросах без ответа.

**4. «разъединитель трехполюсный РГП-110/1000 УХЛ1 с приводом» (ответа в базе нет) → показан
«Разъединитель РГП.2-35.II/1000 УХЛ1» со статусом «та же позиция».**
Напряжение 110 кВ записано внутри марки «РГП-110/1000», разбор его оттуда не достаёт, а ключи марок
близки. Исправит: извлечение класса напряжения из марки аппарата и правило специалиста
«напряжение аппарата совпадает строго» в rules/rules.yaml.

Пятый случай короткой строкой: «погрузка кабеля ОКГТ-Ц-…-81кН автопогрузчиком» — запрос-услуга
с длинным паспортным кодом груза; строки погрузки отличаются только скобкой с грузом, и все
набрали 0.39–0.70. Лечится отдельным сравнением «что грузим» для услуг.

## Что эти ошибки говорят о системе

Главный источник ложных отказов — вид изделия, названный другим словом (3 случая из 4). Тот же
вывод дал большой настроечный набор (8 из 19 у жёстких фильтров). Поэтому словарь видов вынесен
в файл специалиста, а петля подтверждений в прототипе собирает такие пары из работы людей.
