# Задание: большой набор запросов для выбора направления поиска

## Контекст

Тестовое задание Mosaix: поиск аналогов позиций в истории закупок. База 2 381 строка: кабели и провода, оборудование РЗА и связи подстанций, видеонаблюдение и охрана, электроустановочные изделия и щиты, трубы и фитинги, металлопрокат и крепёж, ЖБИ, вентиляция, кабельные лотки, материалы, строки про погрузку и перевозку. Пользователь вводит наименование своими словами, поиск возвращает до пяти подходящих строк базы или честно говорит «не найдено».

Ты пишешь часть большого набора вслепую. Поиск строит другой исполнитель, его код ты не смотришь и не запускаешь.

## Источник

Только файл data/full/rows_all.json: список строк базы с полями row (номер строки Excel, от 2 до 2382), name (наименование как есть) и price. Другие файлы проекта не открывай: ни app/, ни scripts/, ни data/full/prep_all.jsonl, ни data/full/analysis/, ни docs/, ни другие файлы в eval/. Сетевых запросов не делай. Python и grep для поиска по базе можно. Все ссылки на строки пиши номером строки Excel (поле row).

## Что сделать

20 запросов: 16 с ответом и 4 без ответа.

1. **Запрос с ответом.** Возьми позицию из базы и перепиши её в своей манере (ниже). Исходную строку бери только из своей доли строк: номер строки Excel оканчивается на цифры твоей доли. Не копируй строку дословно, запрос должен оставаться однозначным для специалиста.
2. **Верные ответы ищи по всей базе**, не только в своей доле. Дели их на «та же позиция» (same) и «допустимая замена» (substitute). Допустимую замену ставь только там, где специалист, скорее всего, согласится; причину пиши в note.
3. **Важная характеристика** (key) и строки того же вида, у которых она другая (wrong_key): до 15 самых похожих по тексту.
4. **Запрос без ответа.** Позиция, которой в базе нет. Отсутствие проверяй несколькими поисками: по корню слова, сокращениям, латинице и кириллице, разным записям чисел. Если сомневаешься, бери другой пример.
5. **Охват.** Разные категории из контекста, не больше четырёх запросов на одну категорию.

## Чего избегать

- Не бери источником и не ставь верным ответом эти строки, они уже использованы: 3, 81, 86, 130, 136, 159, 279, 292, 339, 428, 462, 467, 494, 559, 588, 614, 635, 644, 752, 816, 860, 871, 887, 893, 918, 923, 933, 1005, 1079, 1171, 1177, 1194, 1288, 1498, 1518, 1525, 1541, 1632, 1643, 1658, 1705, 1869, 1884, 1939, 2015, 2025, 2059, 2141, 2149, 2202, 2342, 2344.
- Не пиши запросы про кабель КВВГ 7х1,5, видеокамеры 2 Мп с вариофокальным объективом, ворота откатные, гофротрубу ПВХ 25 мм, ИБП, трансформатор сухой и огнетушитель.
- Строки, номер которых оканчивается на 7, не бери источником: они оставлены для другого набора.

## Формат результата

Файл eval/big_X.json, где X это буква твоей части (a, b, c, d или e):

```json
{
  "part": "X",
  "style": "твоя манера",
  "queries": [
    {"id": "X01", "query": "текст запроса", "type": "answer или no_answer", "category": "кабели, РЗА, ...",
     "source": [123], "same": [123, 456], "substitute": [789], "key": "сечение 3х2,5 мм²", "wrong_key": [111, 222],
     "rewrite": "что изменено относительно строки базы", "note": "обоснование и сомнения"}
  ]
}
```

У запросов без ответа source, same и substitute пустые, в note напиши, как проверял отсутствие.

Файл eval/big_X.md: таблица на русском для проверки специалистом: id, запрос, тип, источник (номер строки и наименование), верные ответы с наименованиями, важная характеристика, сомнения.

## Проверь себя перед сдачей

- Каждый номер строки существует в базе; источник из твоей доли и не из списка исключений.
- same и substitute не пересекаются с wrong_key; у запроса с ответом непустой same.
- Ровно 20 запросов: 16 с ответом и 4 без ответа.

## Ответ исполнителю

Не больше 60 слов, только числа: сколько запросов каждого типа, сколько в среднем строк в same и wrong_key, сколько запросов с сомнениями. Сами запросы и номера строк в ответе не пиши.
